# Security Guidelines

## Secrets

- All credentials live in `.env` (mode 600), generated by `scripts/generate_env.sh`.
- `.env`, certificates, keys and backups are excluded by `.gitignore`; only `.env.example` with `change_me` placeholders is committed.
- Rotate DB passwords: change `.env`, re-run `docker compose exec postgres bash /docker-entrypoint-initdb.d/01-init-databases.sh` (ALTERs roles), then `docker compose up -d --force-recreate jira confluence`.

## Network

- Only Nginx publishes ports. PostgreSQL, Jira, Confluence and Prometheus are internal.
- `monitoring.local` is restricted to private address ranges.
- Unknown `Host` headers are rejected (`444`).

## HTTP security headers (all virtual hosts)

| Header | Value |
|---|---|
| X-Frame-Options | SAMEORIGIN |
| X-Content-Type-Options | nosniff |
| Referrer-Policy | strict-origin-when-cross-origin |
| Permissions-Policy | camera=(), microphone=(), geolocation=(), payment=() |
| Cross-Origin-Opener-Policy | same-origin-allow-popups |
| Strict-Transport-Security | enabled together with TLS |

`server_tokens off` hides the Nginx version; login endpoints are rate-limited (10 r/s, burst 20).

## TLS

`scripts/generate_dev_certs.sh` produces self-signed certificates for local HTTPS; production uses hospital PKI or ACME certificates. Enable the commented `listen 443` blocks and set `PUBLIC_SCHEME=https`.

## Database

- scram-sha-256 password hashing; least-privilege application roles; cross-database access revoked.
- Backups contain no role passwords (`--no-role-passwords`).

## Data protection (healthcare)

- No real patient or employee personal data in Jira/Confluence/test data.
- Access via groups `hwdt-admins`, `hwdt-developers`, `hwdt-qa`, `hwdt-analysts`, `hwdt-viewers` — least privilege.
- Review Atlassian security advisories monthly and upgrade LTS versions.
